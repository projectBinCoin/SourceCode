# Bincoin Smart Bin — ESP32 firmware

Self-provisioning firmware for the registered smart bins: an **ESP32** reads an **HC-SR04 ultrasonic sensor** (fill level via air gap) and the **battery voltage**, and reports to the Bincoin backend (Supabase). **No per-bin code edits** — every unit runs the same firmware.

## How a bin comes online (user flow)

1. **Power on** — with no WiFi saved (or not calibrated yet) the bin starts a hotspot: **`BINCOIN-SETUP-XXXXXX`**. Join it from a phone/laptop; the setup page opens by itself (or browse `http://192.168.4.1`).
2. **Step 1 — WiFi:** pick your network from the list the bin scanned (only 2.4 GHz networks appear — the ESP32 can't use 5 GHz), type the password, **Test & Save WiFi**. The bin tries the password live while the hotspot stays up and tells you on the spot: *connected*, *wrong password*, or *network not found*. Nothing is saved until the join actually works.
3. **Step 2 — Calibrate:** with the bin **empty** and the sensor in its final position, press **Calibrate Now**. Once both steps are done the bin reboots into normal mode.
4. **Copy the device code** shown at the top of the page — `ESP32-XXXXXX|BINC-XXXXXX` — and paste it into the app's **Register Bin** screen. Add a label, pin the location, submit for admin approval.
5. The bin reports every **60 s** (dev cadence; set `SLEEP_SECONDS = 900` for battery deployments).

The admin approval card shows the **sensor-measured inside height** — the device proves its own geometry, so a tall-thin bin or short-wide bin is verified before approval rather than trusting a guessed size.

## Hardware

| Part | Notes |
|---|---|
| ESP32 dev board | Any WROOM-based board (DevKit V1 etc.) |
| HC-SR04 ultrasonic sensor | Mount at the **top center facing down** into the bin |
| 18650 Li-ion cell + TP4056 charger | Battery supply |
| 100 kΩ resistors ×2 | Voltage divider for the battery ADC |

### Wiring

| Signal | ESP32 pin |
|---|---|
| HC-SR04 VCC | **5V / VIN** (required — weak/unreliable at 3.3V) |
| HC-SR04 TRIG | **GPIO 5** |
| HC-SR04 ECHO | **GPIO 18** via **voltage divider** (10 kΩ + 20 kΩ) |
| HC-SR04 GND | GND |
| Battery divider midpoint | **GPIO 34** (ADC1) |
| GND | common ground |

> **Sensor voltage note — CRITICAL:** the HC-SR04 runs on **5 V**, and its ECHO pin outputs a **5 V pulse** — connecting it directly to GPIO 18 will damage the ESP32. Put a divider on the echo line: ECHO → 10 kΩ → GPIO18 → 20 kΩ → GND (drops 5 V to ~3.3 V).
>
> **Battery divider:** two 100 kΩ resistors in series across the battery; midpoint → GPIO 34. Set `BATTERY_ENABLED true` once wired.
>
> **Mounting — blind zone:** the HC-SR04 can't measure anything closer than **~2 cm** to its face — surfaces nearer than that saturate to **100%** in firmware (never false-empty). Mount the sensor dead-centre, aimed straight down; a ~2 cm clearance above the max fill line is enough. (If switching back to the JSN-SR04T waterproof sensor, its blind zone is ~21 cm — mount it that far above the fill line and set `SENSOR_BLIND_CM` back to `21.0`.)
>
> **Mounting — wall echoes:** polished bin walls bounce pings. Firmware rejects them (bounded window + top-quartile trim), but a **foam collar around the sensor head** (~2 cm ring) narrows the beam and kills them physically — do both.

## Flashing (once per batch — identical firmware on every bin)

1. **Board package:** Arduino IDE → Preferences → Additional Board URLs → `https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json` → Boards Manager → **esp32 by Espressif**.
2. **Board:** ESP32 Dev Module · Upload speed 115200.
3. **Edit two constants only** — `SUPABASE_URL` / `SUPABASE_ANON_KEY` (from the app `.env`). Everything else is self-configured.
4. Upload → Serial Monitor at **115200** shows the derived device ID, e.g. `ESP32-A1B2C3`.

## Identity & pairing

- **Device ID** is derived from the chip's factory MAC (`ESP32-<last3MACbytes>`) — unique, unforgeable by typing, no config needed.
- The **pairing code** (`BINC-XXXXXX`) is generated by the device on first boot and kept in flash. The setup page shows it as part of the copyable device code; claiming in the app stores it on the bins row, and the telemetry RPC refuses writes that don't present it.
- A factory reset (RST ×3) generates a fresh code — the old registration then stops accepting this device.

## Runtime behaviour

1. **Wake** (deep-sleep timer, every `SLEEP_SECONDS` — 60 s by default).
2. **Measure** — 7 ultrasonic pings bounded to the calibrated height (+15%), top quartile dropped to kill polished-wall echo bounces, then median → air gap → `fill% = (1 − airGap/height) × 100`, clamped 0–100. Readings under ~2 cm mean trash is at the sensor face → full. No echo at all with no previous reading → `-1` (**sensor fault**, shown as *Fault* in the apps) instead of a fake level.
3. **Report** — `POST /rest/v1/rpc/update_bin_telemetry` with `device_id`, `pairing_code`, fill, battery, air gap.
4. **Response** — the RPC answers `{ ok, recalibrate, need_height, ping, lat, lng }`. `ok:false` means no registered bin matched (Serial prints the device code to claim). `recalibrate` → re-measure the empty height; `need_height` → resend the stored height; `ping` (a pickup was just booked) → take a fresh reading and report again.
5. **Deep sleep** until the next wake.

### Controls

- **Fresh reading now:** press **RST** once.
- **Change WiFi:** **RST ×2** within ~4 s → setup portal (calibration + pairing kept).
- **Factory reset:** **RST ×3** → wipes WiFi, calibration and pairing code.
- Never hold **BOOT** while powering on — that's the chip's ROM download mode, the firmware doesn't run.
- **Re-calibrate:** admin *Recalibrate* action (picked up on the next wake), or RST ×2 → portal → *Calibrate Now*.
- **Setup timeout:** the portal stays up for 10 minutes; if nobody finishes setup, the bin sleeps a minute and retries.
- **WiFi outage:** saved credentials are **never** deleted automatically — a router outage just means retries. After 3 failed wakes in a row the portal also opens (with a "can't reach" banner) so a changed password can be fixed; the bin keeps retrying the saved network on every wake.

## Security notes

- The **anon key** is public by design — RLS applies. The demo-phase RLS is permissive; tighten per-user before production.
- `setInsecure()` skips TLS certificate validation for simplicity. For production, pin Supabase's root CA via `client.setCACert(...)`.
- Pairing codes mean a stolen device ID alone can't inject telemetry — rotate a bin's code by re-registering it.
